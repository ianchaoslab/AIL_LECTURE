1. MVP가 확인하려는 것 📝

"메모, 할 일, 알림을 앱 3개로 나눠 쓰는 것이 귀찮은 사람은, 한 앱에서 메모를 AI로 정리하고 할 일과 일정으로 바로 옮길 수 있으면 쓸 것이다."

핵심 가치 ✅ (PRD 2-2)

  1. 메모, 할 일, 캘린더, 알림을 한 앱 안에서 끝낸다.
  2. 정리되지 않은 메모를 AI 요약으로 바로 읽을 수 있게 만든다.
  3. 메모 속 할 일과 일정을 다시 입력하지 않고 등록한다.

🟡 AI 요약이 아직 확인되지 않은 이유 ✅
배포된 서버가 Vercel AI Gateway에 요청하면 403 customer_verification_required(고객 확인 필요)로 거부됩니다. 이 Vercel 계정이 AI 기능을 쓰기 위한 확인(결제 정보 등록 등)을 아직 하지 않은 상태로 보여요. 정확한 절차와 비용 조건은 Vercel 안내 화면에서 확인해야 하고, 결제 정보가 걸려 있어 기획자가 직접 해야 합니다.
그동안 AI 요약을 누르면 "잠시 후 다시 시도해 주세요" 안내가 나오고, 메모·할 일·캘린더·알림은 정상 동작합니다. (PRD 7-3: AI는 부가 기능)

MVP에 넣지 않는 것 ✅ (PRD 2-3, 4장)

  • 공유 기능, 휴대폰 앱(iOS/안드로이드), 구글 캘린더 등 외부 연동, 이미지·음성·파일 첨부
  • P1: 메모 검색, 태그, AI 할 일 정리, AI 채팅, 날짜별 모아 보기 (알림 미리 받기는 일정에 "10분 전·1시간 전" 선택만 일부 넣음)
  • P2: 메모 고정, 이메일·푸시 알림, 메모 기반 질문

3. MVP 핵심 사용 흐름 📝

PRD 5장의 시나리오입니다. 5번까지 모두 화면에 구현되어 있고, 2번은 실제 AI 연결 확인이 남았습니다.

  1. 급하게 메모를 적는다. (예: "금 보고서 팀장 확인 3시 회의 자료")
  2. ✨ AI 요약을 누르면 한 줄 요약, 핵심 내용, 발견된 할 일·날짜가 나온다. AI 연결 미확인
  3. 발견된 할 일의 마감일과 알림 시각을 확인·수정하고 할 일로 추가를 누른다. (사용자가 확인한 뒤에만 저장) 구현
  4. 캘린더에 표시된다. 완료
  5. 정해진 시각에 앱 안에서 알림이 뜬다. 완료

4. 단계별 개발 결과

단계내용결과
3단계앱 내 알림할 일은 알림 시각, 일정은 "정각·10분 전·1시간 전" 선택. 15초마다 확인하고, 닫아 둔 사이 지난 알림은 "놓친 알림"으로 알림. 켜기/끄기 스위치와 브라우저 알림(허용 시) 지원
4단계AI 메모 요약서버 파일 api/summarize.js + 메모 화면의 요약 영역. 결과는 원본을 덮어쓰지 않고 따로 저장하며 "저장 / 다시 요약 / 버리기" 제공
5단계메모 → 할 일 변환요약에서 찾은 할 일을 줄마다 고쳐서 추가하거나 "남은 할 일 모두 추가"(확인창 거침). 중복 추가 방지

4단계 서버 구조 ✅

  • Vercel Function이 Vercel AI Gateway를 호출합니다. 모델 기본값은 anthropic/claude-haiku-5.5이고 환경변수 AI_MODEL로 바꿀 수 있어요.
  • API 키를 코드나 화면에 넣지 않았습니다. Vercel이 서버에 자동으로 주는 인증 토큰을 씁니다. (PRD 7-1)
  • 비용·남용 방지: 메모 4,000자 제한, 답변 길이 제한, 한 사람당 1분 6회·1시간 40회, 서버 전체 1시간 300회, 같은 사이트에서 온 요청만 허용.
  • 단, 사용 횟수 제한은 서버 메모리에 있어서 대략적인 제한입니다. 확실한 비용 상한은 Vercel 대시보드의 AI Gateway 예산 설정으로 따로 걸어야 해요.
  • 메모 내용이 외부 AI 서비스로 전송된다는 안내를 요약 버튼 아래에 표시합니다. (PRD 7-1)

5. 지금 알려진 한계 ✅

  • 저장은 브라우저 안에서만 됩니다. 다른 기기·다른 브라우저에서는 보이지 않고, 브라우저 데이터를 지우면 사라집니다. (PRD 7-3)
  • 알림은 앱 화면을 열어 둔 동안만 울립니다. 닫아 둔 사이의 알림은 다시 열 때 "놓친 알림"으로 알려 줍니다. (PRD 4-4)
  • 로그인이 없어서 사용자 구분이 없습니다. 누구나 배포 주소로 들어와 AI 요약을 쓸 수 있어서 비용 관리가 필요합니다.
  • AI 요약의 정확도(특히 날짜 해석)는 실제 AI 연결 후 사용해 보며 확인해야 합니다.

6. MVP 검증 방법 📝

PRD 10장 원칙대로 목표 숫자는 첫 테스트 뒤에 정하고, 먼저 측정할 항목만 적습니다.

측정 항목확인하려는 것
메모 중 요약 버튼을 누른 비율요약이 필요한 기능인가
AI가 제안한 할 일 중 저장한 비율제안이 쓸 만한가
알림 설정 후 실제로 확인한 비율알림이 제 역할을 하는가
테스트 사용자 한 줄 소감: "앱을 따로 열지 않아도 되는가?"핵심 가설이 맞는가

⚠️ 위 측정 항목 중 일부는 사용 기록을 모으는 기능이 아직 없어서 지금은 숫자를 볼 수 없어요. 처음에는 사용자에게 직접 물어보는 방식으로 시작해도 됩니다.

7. 위험 요소 📝

위험대응

누구나 AI 요약을 호출할 수 있어 비용이 늘 수 있다입력·횟수 제한(적용됨), AI Gateway 예산 상한 설정(직접 필요), 필요하면 로그인 추가
AI가 날짜, 시간을 잘못 이해한다저장 전에 사용자가 확인(적용됨)
메모에 민감한 개인정보가 들어간다입력 안내 문구와 AI 전송 안내(적용됨)

8. 직접 결정·진행해야 하는 것

  1. AI를 어떤 방식으로 쓸 것인가? (결제 정보가 걸려 있어 직접 진행)
    • 방법 A: Vercel 대시보드에서 AI Gateway 이용을 위한 계정 확인을 진행한다. (현재 코드 그대로 동작할 가능성이 높음. 비용 조건은 Vercel 안내 화면에서 확인)
    • 방법 B: 본인이 가진 다른 AI 서비스의 API 키를 Vercel 환경변수에 직접 등록한다. (서버 코드를 그 서비스에 맞게 고쳐야 함)
    • 방법 C: AI 요약 없이 지금 상태로 두고 메모·할 일·캘린더·알림만 사용한다.
